## Objective

Move the model-usage rate guard out of `claude_worker.py` into `claude_rate_guard.py` **without changing behaviour**, and without changing how the guard is configured. Tests and the worker configure the guard through values on the `claude_worker` module (`RATELIMIT_PATH`, `USAGE_PATH`, `RATE_LIMIT_WARN_SECONDS`, `RATE_LIMIT_COOLDOWN_SECONDS`, `_process_usage_window`). Those must still be read when the guard runs.

Unlike PR #27, this is not a verbatim move: to keep that state in `claude_worker`, the extracted functions take it as parameters. Equivalence is therefore shown by the unchanged existing tests, new call-time tests, and a differential check of base against candidate.

## Acceptance criteria

1. **Logic preserved.** Each function in `claude_rate_guard.py` matches the corresponding base function in `9287144:claude_worker.py`, except that module globals became parameters and rebinding `_process_usage_window` became a returned list. Conditions, arithmetic, boundaries (`timestamp >= cutoff`), file formats, exception handling, return values, reason strings and log messages are unchanged.
2. **No reverse dependency.** `claude_rate_guard.py` does not import `claude_worker`, and logs on the `"claude_worker"` logger.
3. **Compatibility preserved.** All of these remain on `claude_worker`: `rate_limit_reason`, `_read_holdoff`, `_read_usage`, `_write_usage`, `_purge_old_usage`, `_current_usage_total`, `_record_usage`, `_begin_holdoff`, `_end_holdoff`, `record_rate_limit_alert_sent`, `RATELIMIT_PATH`, `USAGE_PATH`, `RATE_LIMIT_WARN_SECONDS`, `RATE_LIMIT_COOLDOWN_SECONDS`, `_process_usage_window`, `_rate_limit_alert_sent`. The wrappers read that state at call time and store back any returned window, so values patched on `claude_worker` are the ones used. `tests/test_rate_holdoff.py` is unchanged and passes.
4. **Nothing else changes in `claude_worker.py`** beyond the added `import claude_rate_guard`, the wrappers replacing the guard bodies, and the cooldown rationale comment moving into `claude_rate_guard`'s docstring. It stays under 50,000 characters.
5. **Tests.** No existing test file is modified. `tests/test_claude_rate_guard_extraction.py` tests what it claims.
6. **Protected paths.** Nothing under `controller/` or `hub/hub.py` changes; no Tower deployment is needed.
7. **Equivalence evidence.** The differential check in `verification.txt` §7 is a sound comparison of base against candidate, and reports zero differences.
