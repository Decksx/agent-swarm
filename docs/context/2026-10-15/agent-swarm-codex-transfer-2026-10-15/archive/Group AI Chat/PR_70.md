+    reported, so nothing a remote or a credential helper might print can reach
+    the ledger through a refusal message.

## The defect

A review activation carries `repo_location`, recorded by the controller at issue time exactly as `expected_candidate` is. The worker read it, compared it against its own `REVIEW_REPO`, warned on a mismatch, and reviewed in `REVIEW_REPO` anyway:

```
WARNING activation 0e0ad7e5… names repo_location 'C:/git/agent-swarm' but this
        worker reviews in 'C:/swarm-prod/agent-swarm'; reviewing here and recording both
```

A verdict produced that way names a candidate the reviewer never saw, and nothing downstream can tell the difference. It survived because the two paths had always been the same directory; isolating the production runtime made them differ, and the first task through the pipeline (`T-CMD-99a5880f3e`) blocked on a `rev-parse` failure.

## The contract, clause by clause

| Required | Implementation |
| --- | --- |
| Activation `repo_location` is authoritative | `if declared: repo, source = declared, "activation"` — checked first, no later branch can displace it |
| `REVIEW_REPO` only when the activation names none | `elif configured:` — unreachable when `declared` is set |
| Absent, unreadable, not a git repository, or lacking the pinned candidate → `environment_defect` | four distinct refusals, each with its own message |
| Never fall back to a conflicting environment repository | there is no fallback path after `declared` is chosen; the refusal says `not falling back to another checkout` |
| Never fetch | only `rev-parse --git-dir` and `cat-file -e` are ever run |
| Record both paths, without leaking credentials | `detail` carries `repo_location`, `review_repo`, `repo_used`, `repo_source`; git output is discarded rather than echoed into the reason |
| `repo_location` only from the controller-issued activation | read from the activation record, never from contract, objective or model-shaped payload — the rule `engine._approved_candidate` applies to the candidate, applied here to the repository it is read from |
